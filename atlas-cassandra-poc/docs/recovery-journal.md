# Exact-operation recovery journal

AT-095–099 and AT-102 are a test-only extension of the bounded recovery fence. They do not
replace the existing serial archive adapter or implement a production coordinator.
Hosted [run 37447187294](https://github.com/kverma/codex-playground/actions/runs/37447187294)
passed at `843a17c`; all saved model, race, wire/process and journal histories were
independently audited. Full counts and failed attempts are in the adversarial review.

## Contract

A store has one full state `(guard, value)` and immutable accepted-operation
receipts. A request carries its operation ID, exact expected state and exact next
state. The state change and receipt are one same-table, same-partition conditional
batch. A previously accepted ID returns its original receipt only for the identical
request; a changed request is KEY_REUSE. A new operation with a mismatched expected
state is CONFLICT. Transport exceptions remain uncertain, never a claim that the
write did not happen.

An old success is historical evidence, not current ownership. Replaying it cannot
write the older state back over a later recovery. Callers persist the full request,
including its proposed guard, before sending; they do not remint it after timeout.
Only accepted outcomes are journaled. Conflict is not a durable reservation.

The Cassandra fixture uses separate `(subject, store)` partitions for authority
and hot state. There is no cross-partition transaction. Reads use SERIAL and
mutations QUORUM/SERIAL; no timestamp, TTL or idempotent retry flag is supplied.
Bootstrap is explicit and rejects an existing HEAD. The full expected state is
checked by the conditional mutation, not just a prior read.

## Evidence required

- Eight deterministic model cuts: before-send and after-effect at four abstract
  phases, JSON round-trip of the persisted request, late replays and key misuse.
  These are modeled cuts, not actual transport or process failures.
- Four actually broken journals: state without receipt, receipt without state,
  reapplying historical state and ignoring exact request binding. Each asserts its
  precise rejected event; identical requests pass on the correct model.
- Single-node and cross-DC session contracts: old replay after a later write,
  stale/key-reuse rejection, reopening sessions, and two overlapping identical
  calls yielding exactly one state effect and one identical receipt.
- Six competing-proposal races per topology: different IDs and shared IDs with
  different payloads. Require one exact winner, explicit conflict/key reuse for
  its competitor, full cross-coordinator equality and non-mutating retries.
- Twelve real interruption cases: START, FREEZE, PUBLISH and ACTIVATE each lose
  an unsent request, lose a decoded `[applied]=true` reply, or halt a worker after
  the effect before its normal response. Twenty-four distinct JVMs cover the
  interrupted/resumed pair for each case. Inputs remain byte-identical.
- Each case completes two sequential recovery handoffs around an accepted writer
  edit. The full root/hot observations pass the independent fence checker; each
  store's complete history passes the independent journal specification. Every
  old request replays without changing newer state, and a captured stale writer
  cannot change the recovered hot state.

The halt witness is deliberately written by the worker before `Runtime.halt(86)`;
the normal output must be absent. This witnesses process exit at a chosen boundary,
not machine power failure. Proxy failures require the exact request marker, one
interception, the intended direction/effect, and DriverTimeoutException.

`scripts/audit-recovery-journal.py <extracted-artifact>/evidence` independently
rechecks saved JSON, exact receipts, mutant boundaries, race overlap, wire effects,
24 process IDs and the final retained edit. It does not invoke the Java candidate.

## What this does not prove

The handoff plans are generated by a trusted model and applied sequentially to
real partitions. Arbitrary clients are not authorized to submit state JSON. The
generic journal is not a semantic validator, a concurrent archive coordinator or
a provider edit API. Its receipts are unbounded: no production journal-retention
or safe garbage-collection policy has been selected. Reading a bounded partition
does not establish a large paginated snapshot contract.

Separate partitions on one cluster are not independent failure domains. Logical
offer restoration is not SSTable/whole-cluster rollback resistance. There is no
external authority service, object-store durability qualification, credentials,
provider SLA, backup installation fence, or production archive coverage proof.
PG-COMMIT and PG-CASS remain UNPROVEN.
# Contention and uncertain replies

Actions runs 37493947602 and 37494827327 exposed CAS write timeouts in the
journal and root publication contention tests respectively. The original tests
incorrectly required every initial call to return a definitive answer. These are
failed validation runs, not evidence that the timed-out write did not apply.

The race harness now records each initial result or explicit driver/server timeout
before resolution. Unexpected exceptions still fail. Journal recovery performs
one replay of each unchanged request through the other client and requires exact
original receipts, one effect, and agreement on the complete partition. Definitive
initial results cannot change, and an already durable winner cannot be replaced.
Any timeout during this bounded recovery fails the progress gate; there is no
retry-until-green loop. Original call intervals remain separate from recovery.

The root fixture has no operation journal. With later writers excluded in this
test, a SERIAL read identifies an exact original guard and payload. Only if the
original base remains does the harness allow one unchanged proposal replay.
Both subsequent stale publications must reject. This does not generalize to
historical root resolution after later writers have hidden an earlier guard.
